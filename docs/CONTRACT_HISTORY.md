# Contract history

What each version of the agent contract (`CONTRACT_VERSION` in `hv`, reported by `hv version`) changed,
newest first. This text lived as one trailing comment on the `CONTRACT_VERSION` line of `hv` until #106,
where every `grep` that matched it printed the whole line (18,544 characters at the move). Add the entry for a new contract
here, not on that line. The adapter-facing summary is `docs/AGENT_INTEGRATION.md` §7; release notes are
`CHANGELOG.md`.

## 1.27

Genesis pinning: the declaration that established this hive is recorded locally, and the pin — not the entry timestamp — decides which `owner` declaration is the genesis. Before this, genesis was the earliest valid self-signed `owner` act by `(timestamp, node_id, seq)`, and an entry's timestamp is written by whoever wrote the entry, so a later-arriving declaration carrying an earlier timestamp replaced the established owner and silenced the real owner's subsequent acts (only the current owner's acts are honoured). The pin lives at `$HIVE_HOME/.genesis-pin`, mode 0600, never synced, never journaled, excluded from the signed source manifest and from `git`. It holds `{hive_id, owner_id, genesis_ref, genesis_hash}` and binds the whole entry by hash, so a declaration that copies the `hive_id` and the `owner_id` still fails to match. It is written only by a deliberate act: `hv owner init` pins what it writes; `hv owner pin --set` pins the journal's single self-signed declaration and refuses to choose when there are two (there is no timestamp tie-break, because the timestamp is the attacker-controlled part); `hv owner pin --fingerprint <hive_id>/<owner_id>/<hash8>` pins from an invite before the first pull and is completed into an exact-entry pin once the declaration syncs. Ingest refuses any `owner` act that is not the pinned one, and the projection resolves genesis through the pin, so a rival already on disk loses — an append-only journal never removes it. A node with NO pin keeps the previous rule, so a mixed fleet still converges; `hv doctor genesis` warns there, and fails on more than one declaration or on a pin whose declaration is absent (that state also fails closed at ingest instead of falling back to pre-owner permissiveness). Unsigned entries are refused positionally, closing the class where an unsigned entry took an admitted device's future `(node_id, seq)` and became its chain tip: on a chain this node holds, an entry above the tip or a different body at a held seq is refused; on a chain it does not hold, only a verified first pull is accepted — one batch reproducing that peer's whole advertised chain, window hash for window hash from seq 1, which only the outbound pull path can present. A node that has not pinned serves no journal to a remote caller and accepts no push: `/sync/hello`, `/sync/chunk` and `/sync/ingest` answer 403 while `/hive/info` and `/sync/merkle-root` stay open, and loopback is never gated. `/hive/info` and `/sync/hello` carry `genesis_fingerprint` INSIDE the 1.26 responder signature, so a joiner cannot be handed a swapped fingerprint. `hive-mind invite` prints the fingerprint after the address (as a path, which every older installer strips), the installer's join path pins it before syncing, and `hive-mind update` pins on upgrade. New: one command (`hv owner pin`), two doctor checks (`genesis`, `unsigned`), one response field. No journal change and no wire break: an older node ignores the new field, and a pre-1.27 node keeps the old genesis rule until it upgrades (projection skew, never divergence).

## 1.26

Responder-signed `/sync/hello` and `/hive/info` (#107), sync `protocol_version` 3. A caller that signs its request sends a `Hive-Auth-Nonce`; when it is well formed (32 to 64 hex characters) and the responder has a device-key identity, the responder adds `hello_sig: {alg, device, pub, sig}` to its answer, an Ed25519 device signature over `hive-hello-v1`, the path, the nonce, its `node_id`, `hive_id`, `advertised_addr`, `protocol_version` and the sha256 of the canonical JSON of the rest of the response. It signs whether or not the caller's own envelope verified, inside the request slot and rate limit every request takes. A `HIVE_NODE_ID` or hostname identity, or a request without a nonce, gets the unchanged unsigned answer. The caller (`sync_common.verify_hello`) reaches one outcome: `verified` (the signature binds our nonce and path, the key's fingerprint is the `node_id`, same hive or none on one side, admitted and not purged once an owner exists, and `advertised_addr` is the host:port contacted), `addr-unproven`, `unadmitted`, `purged`, `unsigned` or `invalid` (a bad signature, a replay, a foreign key, another hive), plus an `other-device` flag when the `.peers.json` id names another device. A new local setting, separate from `sync_auth`, decides what a round does with it: `hv sync auth --outbound off|permissive|enforce` (`HIVE_SYNC_AUTH_OUTBOUND`, then `.peers.json` `sync_auth_outbound`, default `permissive`). `permissive` flags and never changes behaviour; `enforce` pushes only to a verified peer, only pulls from an unsigned, addr-unproven or unadmitted one, and skips a purged or invalid one. There is no ratchet, the claimed `protocol_version` plays no part, and the merkle-root shortcut stays unsigned. A verified hello is recorded as a #7 sighting (`"via": "outbound"`). `hv doctor`'s `peer-address` now also asks a failing entry's candidate hosts (tailscale names, other sightings, its join-request URL; at most 8, 3 s each) for a signed `/hive/info` and repoints only to one that answers `verified` for exactly that device at the address asked; an address that answers is never rewritten. A new advisory check, `peer-identity`, reports each answering peer's outcome and protocol and whether the fleet is ready for inbound and outbound enforce. One new flag, no new command, no journal change. Mixed fleets keep syncing: an old caller ignores the field, and a new caller sees an old responder as `unsigned`, which changes nothing unless it opted into outbound enforce.

## 1.25

Owner forgets: close the pre-genesis grandfather by policy (#122 step 2). A new governed config key, `forget_writers`, is set with the existing `hv config set` (no new command): `legacy` (default, unchanged: an owner-source forget positioned before the genesis owner is honoured without a signature) or `owner` (only a forget signed by the owner as of its position counts). It rides the existing owner-signed `set-config` act, honoured only from the owner current at its position; the latest act wins; any other value is ignored (fail closed to `legacy`). It stores no journal refs, so no re-keying can orphan it (#130); a legitimate legacy forget is kept by re-issuing it signed with `hv retract --owner`. `hv config set forget_writers owner` refuses while closing would bring a fact back, listing each with its two remedies (`hv retract --owner` to keep it, `hv unforget` to release it); no new flag. `forget-authz` reports the closed state and hints the close while open. A generic `ratify` verb was considered and deferred past 2.0 (hive `h:65fc331d0d`). No wire change: a pre-1.25 node lands the act and ignores the unknown key, so it keeps honouring the grandfather until it upgrades (projection skew, never divergence).

## 1.24

Revoke a decision (#45). `hv decide --revoke <sid> --rationale "<why>"` (MCP/Hermes `hive_decide(revoke=…)`) withdraws a decision that was wrong, with no replacement: ONE decision tagged `revocation` (content `Revoke <sid>: <the target's first line>` unless given; additive payload field `revokes: <ref>`) plus ONE `supersedes` link through `_link_payload`. `content` becomes optional only with --revoke; --revoke and --supersedes are mutually exclusive; the target is resolved and kind-checked, and a missing --rationale is refused, before any write. No new projection: the target's `superseded_by` is set exactly as by --supersedes, and only when the link is `hard` (§5). The confirmation is derived from the authority the projection gives the link, not from --source: `Revoked decision …` when hard, else `Revoke of decision … recorded …; NOT in effect until the owner, or the device that wrote the decision, re-runs `hv decide --revoke`` (listed by `hv doctor` link-authz). `hive_decide` also gains `supersedes`, which had no MCP/Hermes path since 1.19; a parity test now covers `decide` flags as it does `remember`'s. No wire change, no skew: a pre-1.24 node projects a revocation as an ordinary superseding decision.

`hv unforget <fact> --reason` (#46), owner-only and off MCP, journals an owner-signed `retract` carrying `unretracts_ref` (no `retracts_ref`, so a pre-1.24 node skips it: projection skew, never divergence). In `_content_evidence` the owner acts on one content form a timeline sorted on (timestamp, node_id, seq); the latest honoured act wins. Honoured = signed by the owner AS OF its position (`_owner_at`), which fixes the Q1 resurrection of a previous owner's forgets after a transfer/succession/election; a forget before the genesis owner stays grandfathered (#122); an unforget never is. Owner acts no longer move `last_ts`, so an unforgotten fact re-derives from its surviving evidence and an ignored forged forget no longer refreshes a fact's decay clock.

## 1.23

Links carry owner authority only when a PERSON writes them (#114). One builder, `_link_payload`, for all eight link kinds the CLI writes (resolves, supports, contradicts, extends, outcome-of, supersedes, informed, entity; `outcome-of` and `informed` were built inline before), and it owner-signs only when this machine holds the owner key AND the source is `manual`. Every agent source is device-signed as on a member device, so an agent on the owner device no longer writes `hard` supersedes/resolves against other devices' entries. `hv decide` and `hv entity link` gain `--source` (D-6), so an agent's decision is no longer attributed to a person. Write confirmations say `(owner-signed: source manual)` or `(device-signed: source <src>)`. An omitted --source still means `manual` (#119). No wire change; journal shape unchanged (owner_sig stays optional).

## 1.22

`extends` link kind (#115) — `hv remember --extends REF` / MCP `hive_remember(extends=…)` say "builds on" a fact, idea or decision without evidence semantics: an edge row in `links` only, never weighed on any channel; additive, no wire change, no skew (a pre-1.22 node lands the link and projects it to nothing).

## 1.21

Labels fail closed and the grounding rule covers assertions. #72: one `_channel` normaliser for every reader; absent = `sense`, an UNRECOGNISED channel = `introspect` (never observation weight; the outcome rule already counted only `sense`); trust velocity counts `act` with `sense` as before and an unknown label with `introspect`. An unrecognised source class stays 1.0 on purpose (a class can only claim a discount, so unknown = no discount = absent). #73: the grounding rule (design §0.1) covers fact ASSERTIONS, not only links: a `fact` entry whose `channel` is `introspect` weighs `introspect_support_weight` (governed, default 0) in `_content_evidence`, so two agents restating the same reasoning never corroborate each other. The fact still lands (row, search, link target) at confidence 0 with no evidence timestamp until an observation supports it. No CLI, output-schema or wire change; a mixed 1.20/1.21 fleet computes different confidence for introspect facts until every node upgrades (projection skew only; Merkle stays converged).

## 1.20

`idea` journal type — a hypothesis whose confidence is EARNED, never asserted (design §6). Fourth `_PASS1` type → new `ideas` table (facts minus importance/access_count, plus utility); `hv propose "…" [--tags] [--channel]` / MCP `hive_propose`; an idea starts at confidence 0.0 and moves ONLY via `supports`/`contradicts` links (`_idea_evidence`, a clone of `_content_evidence` keyed by the idea's JOURNAL IDENTITY, not its content — two agents restating the same guess are two ideas, never corroboration; ideas never add positive evidence to a fact with identical text). Grounding rule made explicit for ideas: a link whose `channel` is `introspect` weighs `introspect_support_weight` (default 0), and an idea's own write-path channel defaults to `introspect` (a hypothesis is internal state), so two LLM sessions cannot talk a hypothesis into confidence — only `sense`-channel observations can. Read surface: `hv search --kind {all,fact,decision,idea}`; under `all` an idea appears only once it has earned confidence > 0, `--kind idea` lists them all; JSON rows gain `kind: idea`; `i<N>` local-id prefix is a kind-checked CLI convenience, `ref` is the stable form. Attention, not announcement: ingest of a PEER's idea appends an `idea-arrived` line to the local, non-journaled bus log `$HIVE_HOME/.bus/introspect.log`, and the session-start digest prints up to 3 open ideas (effective confidence below the local display knob `OPEN_IDEA_THRESHOLD`, default 0.3, newest first) as a standing invitation to weigh in. NO WIRE CHANGE, NO VERSION SKEW (a 1.19/1.18 node lands an `idea` and ignores it).

## 1.19

Generic `link` journal type — ONE content type with an OPEN `kind` vocabulary replaces the three bespoke link mechanisms for new relationships: payload `{kind, from_ref, to_ref, data, source, channel?, owner_sig?}` where refs are journal identities `[node_id, seq]` (never local ids); ONE pass-2 resolver (`resolve_link`/`_LINK_RESOLVERS`) folds the seven kinds it knows (`supports`, `contradicts`, `supersedes`, `resolves`, `entity`, `informed`, `outcome-of`) into a new generic `links` edge table and an UNKNOWN kind lands and projects to nothing (the `announce` rule — a 1.19 and a 1.20 node never diverge over vocabulary). LINKS ARE EVIDENCE, NOT COMMANDS (design §5): `_link_authority` returns `hard` only when the payload carries an `owner_sig` valid for the owner AS OF that journal position (`_is_authorized_writer`, the 1.16/1.17 check — a device key is never the owner key) or the verified signer is the target's author; from any other admitted device a `supersedes`/`resolves` is DOWNGRADED to weigh-only (recorded as `links.authority = evidence`, surfaced by the new advisory `link-authz` doctor check, ratified by re-issuing owner-signed), so a compromised admitted device can never erase, only weigh. `supports`/`contradicts`/`resolves` fold into `_content_evidence` as identity-weighted ± evidence on the target fact (cap_self, same-device discount and admission apply unchanged); grounding rule: a link whose `channel` is `introspect` weighs the new governed knob `introspect_support_weight` (default 0 — reasoning never moves confidence; absent channel = `sense`). `informed`/`outcome-of` are edge rows only (projected by 1.19 PR3/PR4). NO INGEST CHANGE (content is gated by admission, not type) and NO WRITE-PATH CHANGE: `--supersedes`/`--resolves`/`entity link` keep emitting their legacy fields (PR2b switches them once the fleet is on 1.19; never dual-emit), old resolvers stay forever, nothing is migrated. NO WIRE CHANGE, NO VERSION SKEW: a 1.18 node accepts and persists a `link` (valid signature, admitted device), its rebuild skips the unknown type, Merkle stays converged.

## 1.18

Capsule-addressability for silent devices — new authority-less, DEVICE-signed, kind-discriminated governance act `announce` (fixed envelope {action, kind}; kind-specific fields under `data`; first kind: `key`), whose only purpose is to EXIST as a signed entry carrying the device's pub so `_recipient_pubkeys` can harvest an identity-bound Curve25519 key for an admitted device that never authored an entry (direct owner admit, zero writes — it could never receive capsules and `doctor` warned forever; join-request devices were always fine, their request is signed). Ingest allowlists `announce` beside `join-request` (the ONE wire change); the projection ignores it entirely (grants nothing, deliberately projection-invisible); the trust model is UNCHANGED — a payload-carried key is still never a source, the pub is harvested off the signed entry under the same fingerprint binding. Unknown announce KINDS are accepted and ignored, so future kinds ride through 1.18 nodes with no skew window. `hv key announce` (alias `hv config identity announce`) emits it, guarded to once-ever per device — the guard uses the same pub↔device_id binding as harvest, so a planted pub on a spoofed unsigned entry can never suppress it; `hv doctor --fix` auto-emits on an owned hive (the 15-min timer self-heals the fleet). VERSION SKEW: a pre-1.18 peer deterministically REJECTS an announce on ingest (not in its allowlist, no owner_sig) and shows an advisory `diverged` against upgraded peers; nothing is lost — sync is stateless Merkle-diff re-pull, so the entry lands automatically on that peer's next round after IT upgrades (`hv sync now` alone won't clear it before then). Upgrade always-on nodes first, the emitting device last for a zero-noise rollout.

## 1.17

Cell/comb write-authorization at the PROJECTION — `_cell_state`/`_comb_state` now apply the same projection authorization as capsules (hive #58), but under a SEPARATE `cell_writers` policy (default `owner`; `fertile` = any admitted device), so a hive can keep executable definitions owner-only while running capsules fertile or vice versa (hive #60). A cell DEFINES what an agent/tool runs, so a malicious redefinition is code-injection-equivalent; previously `hv wire --add` appended cell/comb entries with NO write gate, so any admitted device could redefine a cell. BEHAVIOR CHANGE: under the default `cell_writers=owner` only the owner may publish cells/combs — `hv wire --add` now refuses a non-owner write and the projection declines a non-owner-signed cell/comb entry (it still LANDS in the journal; every node folds it away, convergence-safe). Cells/combs are owner-signed on write like capsules; new advisory `cell-authz` doctor check surfaces any now-unhonored definition. Migration-safe on hives with no non-owner cells (the doctor check makes any change visible).

## 1.16

Capsule write-authorization at the PROJECTION — `_capsule_state` now declines to honor a `capsule` entry whose signer was not the authorized writer (the owner AS OF that entry's journal position under the default `capsule_putters=owner`; any admitted device under `fertile`), closing a hole where a compromised ADMITTED device could supersede or tombstone ANY capsule by appending a journal entry directly, bypassing the CLI-only `capsule_putters` gate (a targeted denial-of-secret). Convergence-safe: the entry still LANDS in every journal/Merkle; every node deterministically folds it away — no ingest/sync/admission change. Owner authority is POINT-IN-TIME via an additive read-only `gov['owner_timeline']`, so a prior owner's seals survive a transfer/succession/election (hive #58). Unsigned capsule entries are declined once an owner exists; a crypto-less (stripped) build keeps honoring (it already hard-fails the `crypto-modules` doctor check) rather than silently emptying capsules (hive #61). New advisory `capsule-authz` doctor check surfaces any now-unhonored entry. cell/comb authz + a separate `cell_writers` policy land in a follow-up PR (hive #60).

## 1.15

Decisions become first-class taggable + searchable — `hv decide --tags` records project/topic tags on a decision (journaled additively in the decision payload; projected to a new `decisions.tags` column; pre-1.15 decisions read back untagged), and `hv search` now ALSO returns matching decisions (LIKE over content/rationale/tags, newest-first, superseded ones flagged) alongside facts, so a project decision is findable by tag/text instead of by its node-local, rebuild-unstable `#id`. `hv search --format json` stays a flat list but each row gains a `kind` discriminator (`fact`|`decision`); a `min_confidence>0` consumer naturally drops decisions (they carry no confidence). MCP `hive_decide` gains a `tags` arg (parity). Additive journal field, wire-compatible; no sync/admission/CLI-removal change.

## 1.14

Standards-anchored crypto — the bundled symmetric layer moved from a hand-rolled SHA-256-CTR keystream + HMAC encrypt-then-MAC to pure-Python ChaCha20-Poly1305 (RFC 8439, `chacha20poly1305.py`), so the self-test pins the RFC's PUBLISHED vector instead of a self-minted byte string and the crypto reviewer audits one analyzed AEAD, not a bespoke composition. `_kdf_keystream` is DELETED. Capsules: alg → `x25519-hkdf-chacha20poly1305-v1` (HKDF-SHA256 over the X25519 ECDH stays; only the cipher changed). Owner-seal: `enc` → `scrypt-chacha20poly1305-v2` (scrypt n 2^15→2^16, params bound as AEAD AAD); the v1 read path is REMOVED (breaking for any pre-1.14 escrow/passphrase-export) — `hv owner restore` skips a retired-scheme escrow with a re-`escrow` hint instead of crashing. New hard-fail `keyperm` doctor check: the raw device/owner seeds at rest must be 0600 (the threat model rests on it); `hv doctor --fix` re-tightens. crypto self-test gains the RFC 8439 AEAD KAT (the symmetric layer previously had NO pinned vector).

## 1.13

Self-wiring primitives, phase 0 — `cell`/`comb` first-class, kind-discriminated journal types (deterministic `_cell_state`/`_comb_state` projections like `_governance_state`; NOT added to `_PASS1`/store.db; they ride sync admission-gated as content). `_wire_claude_hooks` generalized to `_wire_agent(cell)` driven by a built-in Claude `kind:agent` cell (byte-identical; `_wire_claude_hooks` kept as a back-compat shim). New top-level `hv wire <name>|--comb|--list|--show|--add` auto-dispatches by the cell's kind (agent→reconcile foreign config; tool→Phase-1 executor) and ABSORBS `hv doctor wire-agent` (kept as a hidden deprecated alias for one release); installer/updater delegate to `hv wire claude`. Additive journal types are wire-compatible; the wire-verb move is the only CLI break. (Phase 1 tool executor + 5 cells, Phase 2 encrypt-to-device capsules, Phase 3 crypto watchdog land next.)

## 1.12

Self-healing agent integration via a STABLE shim — the Claude Code hooks live in a FOREIGN config (~/.claude/settings.json) the daemon self-heal never owned, so a node updated from before a hook existed could run "healthy" yet silently miss half its hooks. Now ~/.claude registers only a stable shim (`scripts/common/hive_dispatch.sh <event>`, one per lifecycle event); WHICH behaviors run per event is decided inside that script — source-controlled, under `hv verify`'s signature — so new behaviors ship by `git pull`, never by re-wiring ~/.claude (only a new event TYPE changes the spec). `hv` holds the ONE shim spec (`_CLAUDE_HOOK_SPEC`/`_wire_claude_hooks`); `hv doctor` adds an `agent-hooks` check and `hv doctor --fix` (the 15-min `hive-doctor.timer`) reconciles: adds missing shims AND prunes legacy direct hooks (so behaviors never double-fire) + relinks the skill, surgically (own hooks untouched, `.bak.doctor` backup first). `hv doctor wire-agent` exposes it; install.sh + the updater delegate to it (no second definition to drift). Foreign-config integrations only (Claude Code today; Codex later reuses the same dispatcher) — plugin agents (Hermes/OpenClaw/MCP) are our signed code and need no shim. Additive, no wire change; adapters unaffected.

## 1.11

Reconciliation verbs — `hv remember --resolves <id>` links a write to a prior fact it corrects and SOFT-RETRACTS that fact (deliberate negative evidence, reversible, never an owner-forget), recording the link on the new row (`facts.resolves`); a new `hv audit` category CONTRAVENED parses prose references (`resolves/supersedes/obsoletes/corrects #N`) and flags any whose target is still live (un-reconciled), surfaced in the session-start boot summary. Additive, no wire change; adapters unaffected.

## 1.10

Sync robustness — the Merkle index now de-dups the journal by (node_id, seq) before hashing (merkle.read_all_entries), so a physically-repeated journal line can no longer shift a chunk hash and fake a permanent peer "divergence" that ordinary sync cannot heal (append_foreign_entries also de-dups by that key, so a peer's correct copy is rejected as a duplicate and the stray row is never removed); deterministic lexicographic tie-break on the canonical encoding so every node picks the same representative. No wire/CLI change.

## 1.9
