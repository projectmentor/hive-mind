- `/v1/peers?probe=0` (and `/api/peers?probe=0`) now answers from the last peer probe this daemon made, so a directly-admitted peer keeps its address. hcns reads that list to pick whom to dial; before, only a device that joined by request had an address there, and the hcns bus was a star around it instead of a mesh. The read never waits on a fan-out: a stale or empty map starts one background probe, at most one every 5 minutes.
